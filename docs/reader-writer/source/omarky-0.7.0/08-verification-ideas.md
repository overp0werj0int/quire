# How omarky verifies itself, and what transfers to a headless Rust renderer

Source repo is `/home/p0werj0int/Projects/omarky` (version 0.7.0). Part A records what omarky does (cited). Part B proposes how each idea maps onto a headless renderer that snaps PNGs and plays scripted input. Part B is proposal, not extraction.

---

## Part A. What omarky does

### A1. Layers

- **VER-01** Unit suites run headless under the app's own JS engine, one file per library module. Counts are align 7, blocks 35, changes 28, code 3, editing 11, fold 7, fonts 6, highlighter 5, inline 13, kshtheme 3, palette 6, ranges 12, runs 9, url 4, words 17 (`test/tst_*.qml`, `tools/test:2-7`).
- **VER-02** Ruby suites cover the launcher (history, native build, version resolver, rewrite, CLI) and run after the QML suites from the same entry point (`tools/test:2-4`).
- **VER-03** End-to-end checks drive a real app instance offscreen over IPC and assert on a JSON state dump. They are `reader/tools/check-live`, `check-theme`, `check-tasks`, `check-sheet [--plain]`, `check-changes` and `writer/tools/check [--plain]` (`reader/tools/check-tasks:2-5`, `reader/tools/check-sheet:2-7`, `reader/tools/check-changes:2-4`, `writer/tools/check:2-5`).
- **VER-04** A screenshot tool renders every sample under six review themes (gruvbox, tokyo-night, catppuccin-latte, rose-pine, flexoki-light, matte-black) at 1400 × 1000 and 800 × 1000, three pages each, for human review (`reader/tools/screenshot:8-15`, `reader/tools/screenshot:53-55`).
- **VER-05** README screenshots are rendered offscreen at 2× from sample documents only, then framed with rounded corners, a hairline edge and a soft shadow on a gradient from the theme's own bg and accent, 1600 px wide (`reader/tools/readme-shots:2-8`, `tools/frame:2-13`, `README.md:177`).

### A2. The driving interface

- **VER-06** A dev instance runs privately and offscreen. Commands are start, open (must hand off to the running instance), state, key, shot, count, log, stop (`reader/tools/dev:2-9`).
- **VER-07** Key specs are a small grammar, `j`, `G`, `ctrl+f`, `shift+space`, `escape`, `enter`, `pagedown`, `backslash`, `plus`, digits, and `type:TEXT` to type into the find field. With the edit sheet open, keys go to the sheet (`reader/ui/app/ReaderWindow.qml:157-180`).
- **VER-08** Other IPC hooks are link (activate an href), hover (set the hovered block), bench, close, pick (choose a version), stop (leave changes mode), task (tick a box on a line) and sheet commands (`reader/ui/shell.qml:122-143`).
- **VER-09** The state dump has title, window size, path, loaded, missing, block count, parse time, reload count, top block index and its source line, scroll offset, progress (3 decimals), outline shown, wide, theme name, bg hex, syntax theme name, column width, zoom, body size, help shown, find state (shown, query, count, current), clipboard (first 200 chars), selection, version and changes state, and edit-sheet state (`reader/ui/app/ReaderWindow.qml:107-121`).
- **VER-10** Screenshot jobs are JSON `{ out, jobs: [{ file, name, w, h, pages, opts }] }`. Each job waits 450 ms to settle, grabs, pages down, repeats. A 240 s watchdog aborts a hung run (`components/Shooter.qml:8`, `components/Shooter.qml:24`, `components/Shooter.qml:43-46`).
- **VER-11** Shot options put the window in a state before the grab, outline, wide, help, find query, reloaded pulse, missing banner, hovered block, compare-from version, fold, edit sheet, version list, and an anchor placed S(26) below the top (`reader/ui/app/ReaderWindow.qml:82-104`).

### A3. Gates and budgets

- **VER-12** Any WARN, ERROR or CRIT line in the app log fails the screenshot run, after filtering a short regex of known external noise (`reader/tools/screenshot:89-95`, `docs/decisions/0008-log-rules.md:1-16`).
- **VER-13** Every end-to-end check ends by asserting a clean log (`reader/tools/check-tasks:2-5`, `reader/tools/check-sheet:2-5`).
- **VER-14** The bench scrolls from the top in 120 px steps, forcing synchronous layout per step, until the end or 5,000 steps. It reports steps, worst ms, mean ms (one decimal), the count over 16 ms, the first 12 slow steps with the block type and language at that point, and total ms (`reader/ui/app/ReaderWindow.qml:138-154`).
- **VER-15** Recorded figures for `samples/long.md` (5,422 lines, about 1,085 top-level blocks) are parse about 45 to 60 ms, launch to rendered about 650 ms, mean step under 1 ms, worst 18 to 19 ms once (`docs/decisions/0009-scrolling-performance.md:1-15`).

### A4. Fixtures

- **VER-16** Samples are kitchen-sink, prose, code, tables, alerts, frontmatter, bare-frontmatter, long (generated by `tools/gen-long`), malformed, empty, sample, `real/reader-spec.md`, and a scripted git history for changes mode (`samples/changes/make-repo`, `proposal-before.md`, `proposal-after.md`) (`samples/`).
- **VER-17** The malformed sample covers 24-deep lists, 15-deep quotes, a 3,000-character line and binary junk. The page must render without blanking or collapsing the column (`samples/malformed.md`, `REPORT.md`).
- **VER-18** Live-reload checks script real file operations, append, insert three blocks above the reading position, atomic rename as editors save, a burst of 10 writes, delete, restore, and print reloads, block count, top index, top line, offset and missing after each. The top block must stay the same block (`reader/tools/check-live:2-18`).
- **VER-19** Theme checks build a fake theme tree and switch it the way the OS tool does (remove the current theme directory, move the next one in, rewrite the name), printing colours, syntax theme and scroll position after each of four switches. The real theme is never touched (`reader/tools/check-theme:2-7`).
- **VER-20** Task checks assert that a tick and a clear each change exactly one character in the file, the page reloads with the new state, and a stale line is refused with the file unchanged (`reader/tools/check-tasks:2-5`).
- **VER-21** Rewrite checks run against a fake `claude` binary, with the user's style guide and checker excluded (`reader/tools/check-sheet:15`, `writer/tools/check:12`).
- **VER-22** Every check that involves the optional native painter also runs `--plain`, so the fallback path is proven (`reader/tools/check-sheet:6-7`, `writer/tools/check:4-5`).

### A5. Human review practice

- **VER-23** Font and look decisions were made by side-by-side screenshots under one theme and size, with zoomed crops (`docs/decisions/0005-heading-font.md:1-6`, `docs/decisions/0007-code-font.md:1-6`).
- **VER-24** Scroll feel was matched to a reference app (the user's Chromium browser) by reading both stacks' source for the scroll unit and fling curve rather than by tuning by eye (`docs/decisions/0011-touchpad-scrolling.md:1-17`).

## Part B. What transfers to a headless Rust renderer

Each idea names the spec items it would guard.

- **VER-25 State dump as the main assertion surface.** Expose one serialisable snapshot of the reader with the VER-09 fields that apply (top block index and source line, scroll offset, column width, gutter, body size, zoom, progress, find count and current, outline shown, wide, toast text, banner text, clipboard). Most behaviour in `03-reader-behaviour.md` is then testable without pixels. Guards RD-10 to RD-61.
- **VER-26 Scripted input with omarky's key grammar.** Accept the same spec strings (`j`, `G`, `g g`, `ctrl+f`, `shift+space`, `type:foo`, `escape`) plus `wheel:DY`, `swipe:DY,DT,...` with lift timing, `click:X,Y`, `rclick:X,Y`, `hover:X,Y`, `drop:PATH`. Reusing the grammar lets omarky's check scripts be ported almost line by line. Guards RD-80 to RD-85.
- **VER-27 A virtual clock.** Drive animations and timers from an injected clock so a script can say "advance 110 ms" and assert the scroll landed, or "advance 1599 ms" then "1601 ms" for the toast. This makes every duration in the spec (110, 240, 150, 160, 900, 1100, 1400, 1600 ms) an exact assertion rather than a sleep. Guards RD-22, RD-24, RD-33, RD-98, BLK-51.
- **VER-28 Geometry assertions from a layout dump.** Dump each block's type, source range, x, y, width, height and gap-above. Then the rhythm table (PAGE-54 to PAGE-67), measure and gutter formulas (PAGE-21 to PAGE-27), list indents and marker positions (BLK-18 to BLK-26), and table column widths (BLK-63 to BLK-65) become numeric tests at several window widths and zooms. This catches regressions screenshots hide.
- **VER-29 Golden screenshots on the omarky matrix.** Render each sample under the six review themes at 1400 × 1000 and 800 × 1000, three pages each, plus the 2× README scenes. Store goldens and diff with a small per-pixel tolerance (font rasterisation varies). Keep the shot options (outline, wide, help, find, reloaded, missing, hover, anchor) as scene parameters so chrome states are covered. Guards visual items across files 01 to 03.
- **VER-30 Side-by-side parity shots with omarky.** omarky's own offscreen screenshot tool can render the same samples under the same themes and sizes. Rendering Quire's version at the same size and comparing (overlay, difference image, or crops of a heading, list, code block and table) is the most direct check that "the page feels like omarky". Measure ink positions (first baseline, left text edge, marker x) rather than requiring pixel equality, since rasterisers differ.
- **VER-31 Clean-log gate.** Fail any headless run on a warning or error log line, with an explicit, commented allowlist. Guards DEC-0008.
- **VER-32 Scroll bench.** Port the bench as a headless command (120 px steps, synchronous layout, worst, mean, count over 16 ms, slow-step list with block type and language) on `long.md`. Budget is worst under 16 ms and mean under 1 ms. Guards RD-30.
- **VER-33 Fling curve as a pure function test.** Test the fling simulation against the closed form speed(t) = (|v0| + 172) e^(−3.7 t) − 172, the 50 px/s floor, the 20,946 px/s cap, the 200 ms lift window and the three-sample velocity. Separately, record a real swipe's raw deltas on the target machine and replay them as a script to calibrate the 12× factor. Guards RD-26 to RD-28.
- **VER-34 File-system scripts for reload.** Port check-live's six operations against a temp file and assert the top block identity after each, plus the 150 ms debounce (10 writes give one reload) and the 1000 ms re-check while missing. Guards RD-10 to RD-17.
- **VER-35 Theme switching.** Switch themes in a running headless instance and assert that role colours, syntax colours and scroll position update without reload. Include a theme whose accent is within RGB distance 24 of its fg to check the link fallback, and a light theme to check every light/dark alpha pair. Guards PAGE-32 to PAGE-53.
- **VER-36 Task tick round trip.** Assert one-character file diffs for tick and clear, CR line endings kept, a stale line refused with the file byte-identical, and no click while missing or with the sheet open. Guards RD-73 to RD-77.
- **VER-37 Malformed and edge fixtures.** Reuse omarky's samples verbatim (copying the files keeps parity), and assert the page renders, the column width stays at its formula value, and no log errors appear. Guards BLK-08, BLK-21, BLK-34.
- **VER-38 Parser parity tests.** Port the blocks, inline, url and palette unit suites as table tests over Markdown strings (slugs with repeats, task detection, alert detection, diff line kinds, numeric column detection, front-matter kinds, gallery detection, comment dropping, autolink edge cases). These pin the block model independently of rendering. Guards BLK-01 to BLK-98.
- **VER-39 Font face check.** Render a plain paragraph and assert the Regular face was used, not Bold, since the installed Quattro S Bold declares a regular weight. Guards PAGE-02 and DEC-0003.
- **VER-40 Reduced motion.** Run the scripted suites once with reduced motion on and assert that every move lands in the same frame, no fling occurs, and the fade-in is skipped. Guards PAGE-84, RD-27.
