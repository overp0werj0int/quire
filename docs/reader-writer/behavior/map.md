# Map mode

Map mode is Quire's live mindmap editor over a note's Markdown, beside Source (the writer) and
Preview (the reader) (decision 0014). It uses Markmap (`https://markmap.js.org/`,
`github.com/markmap/markmap`) for its tree semantics and visual grammar, and writes every edit
back to the same `.md` file through Quire's save path so Markdown stays the single source of
truth.

Notes on reading this file:

- The format and status tags follow `README.md`. Every in-scope item uses `[adapted: 0014]`.
  Items are checked by behaviour, not by unit tests: a `script` item is a case in
  `desktop/tests/cases/map/` that replays input on a note and checks the note on disk or a
  probe reading (`desktop/tests/cases.py`).
  Where Quire departs from Markmap, the item states Quire's behaviour first and summarizes
  Markmap after `markmap:`.
- `B` is the body size setting (`PAGE-10`), 14 px by default. Worked pixel values in brackets are
  for `B` = 14 and scale with `B / 14` unless marked fixed. `round()` rounds half up (`page.rs`).
- Colour names (`bg`, `text`, `strong`, `dim`, `faint`, `ghost`, `accent`, `hover`, `hairline`,
  `hairlineSoft`, `panel`, `card`, `chipFill`, `chipEdge`, `blue`, `green`, `orange`, `magenta`,
  `cyan`, `yellow`, `find`, `find_current`) are the page roles derived from Quire's active theme
  (decision 0005, `roles.rs`).
- Keys are written in the `omarky` preset unless both presets are listed (decision 0003). `Ctrl`
  means `Cmd` on macOS.
- Citations starting with `markmap:` point into `github.com/markmap/markmap` at tag `v0.18.13`
  unless prefixed `markmap v1:` (`v1.1.1`). Citations starting with `quire:` point into this
  repository.

## 1. Node model and Markdown mapping

- **MAP-001** [adapted: 0014] [verify: script] The map tree is built from Quire's parsed note (`quire: desktop/src/blocks.rs`, `blocks::build`, CommonMark plus GFM tables, strikethrough, task boxes, `[[wiki links]]`, `#tags`, `![[image]]` embeds, alerts, footnotes and front matter), plus a line scan for `<!-- markmap: fold -->` and `<!-- markmap: foldAll -->` directives and YAML `markmap:` options in fenced front matter. markmap: renders Markdown via `markdown-it` to HTML and parses HTML with Cheerio (`markmap: packages/markmap-lib/src/transform.ts`, `packages/markmap-html-parser/src/index.ts`).
- **MAP-002** [adapted: 0014] [verify: script] When a note has a single top-level `H1` and no visible non-frontmatter block precedes it, that `H1` is the root node. Otherwise Quire synthesizes a virtual root node whose label is the frontmatter `title` field when present, else the note's base file name without `.md` (`quire: desktop/src/md.rs`, `md::base`). markmap: collapses any single-child empty root before reading `frontmatter.title`, leaving an empty root label when neither exists (`markmap: packages/markmap-lib/src/transform.ts:19-31,74-75`; `markmap v1: packages/parse/src/to-tree.ts:81-86`).
- **MAP-003** [adapted: 0014] [verify: script] Every top-level heading (`H1` to `H6`, ATX or setext, as indexed in `Doc::headings`, `quire: desktop/src/blocks.rs`) attaches as a child of the nearest preceding top-level heading with a strictly smaller level number, or the root if none exists. Skipped levels (such as `H3` directly under `H1`) attach directly to that ancestor and keep their true Markdown level (`markmap: packages/markmap-html-parser/src/index.ts:443-452`; `markmap v1: packages/parse/src/to-tree.ts:24-30`).
- **MAP-004** [adapted: 0014] [verify: script] Each list item in a list becomes a child node of its owning heading, root or parent list item. Ordered items render their source number and delimiter (`1. `); task items render a clickable task box (`BLK-28`). A list item's first paragraph (or heading) is its node label; every following block inside that list item (nested lists, indented paragraphs, code blocks, images, tables, quotes, alerts) becomes a child node of that item in source order. A list item whose first block is a code block, diff, image, gallery, table, quote, alert or raw HTML renders directly as that card node. markmap: keeps only nested lists as children of `li` (`markmap: packages/markmap-html-parser/src/index.ts:341-357`).
- **MAP-005** [adapted: 0014] [verify: script] Every non-list content block directly under a heading or virtual root (paragraph, code block, diff block, image, gallery, table, blockquote, alert, raw HTML) becomes a leaf child node or card of that heading or root in source order, so no prose or media is ever hidden. markmap: `v0.18.13` drops plain paragraphs, blockquotes, alerts and raw HTML, and wipes lower-rank children when a heading follows a list under one parent; `v1.1.1` attaches non-list blocks as notes inside the owning node (`markmap: packages/markmap-html-parser/src/index.ts:363-366,429-439`; `markmap v1: packages/parse/src/to-tree.ts:50-79`).
- **MAP-006** [adapted: 0014] [verify: script, state] Front matter (`BLK-85`) is never shown as a branch node. Its `title` feeds `MAP-002` and its `markmap:` block feeds `MAP-011`. When front matter holds any other fields, a compact properties badge (`Properties · N`, in `faint` mono `round(B × 0.72)` [10 px]) sits beneath the root node; clicking it opens Quire's Edit Sheet on the front matter's source lines. markmap: strips front matter completely with no way to view or edit its fields (`markmap: packages/markmap-lib/src/plugins/frontmatter/index.ts`).
- **MAP-007** [adapted: 0014] [verify: script] Thematic breaks (`---`, `***`, `___`), HTML comments and link reference definitions create no map nodes and stay untouched in source. A `<!-- markmap: fold -->` comment on a heading or list item sets that node's initial fold state (`fold = 1`), and `<!-- markmap: foldAll -->` folds that node and every descendant (`fold = 2`) (`markmap: packages/markmap-html-parser/src/index.ts:368,460-473,541-547`).
- **MAP-008** [adapted: 0014] [verify: script, state] When a note defines footnotes (`BLK-80`), all footnote definitions gather under one synthetic `Footnotes` group node at the end of the root's children, folded by default with its count pill (`+N`). `blocks::Footnote` (`quire: desktop/src/blocks.rs`) gains a `lines: Range<usize>` field recording each footnote definition's own source line range, because definitions may be scattered across the file and the `Footnotes` group itself has no contiguous `subtree_lines`. The `Footnotes` group and its footnote children take only Edit (a footnote child opens the Edit Sheet on its `lines`; the group has no edit target), Copy (`Ctrl+C` copies a footnote child's `lines`, or on the group copies all definitions joined by blank lines) and fold (`Space`, `f` or the fold circle on the group); add child, add sibling, delete, paste, image insert, drag-and-drop and keyboard structure moves are refused. markmap: has no footnote group.
- **MAP-009** [adapted: 0014] [verify: script] Every non-virtual structural node stores its exact 0-based exclusive source line ranges: `own_lines` (the node's own block or list-item first lines) and `subtree_lines` (from `own_lines.start` through the end of its last descendant). Every non-virtual structural node's `subtree_lines` is one contiguous range (excluding the synthetic `Footnotes` group, whose footnote children each store their own `lines` range via `blocks::Footnote.lines`), and a parent's structural children appear in strictly ascending, non-overlapping line order (`markmap: packages/markmap-lib/src/plugins/source-lines/index.ts`).
- **MAP-010** [adapted: 0014] [verify: script] Each node has a deterministic `NodeId` derived from its structural path of `(node_kind, content_hash, ordinal_among_equal_siblings)`. Duplicate labels under one parent stay distinct, and folds, selection and animations survive edits elsewhere in the note and outside reloads. After a Map gesture (inline edit, move, promote, demote, heading level change, task toggle), the selection and fold set are remapped from old to new `NodeId`s for the edited or moved subtree (matching by structural position within the subtree, or falling back to `own_lines.start` when a raw edit changes structure per `MAP-017`), so selection and descendant folds survive renames and moves. markmap: keys nodes by `parentId.id + simpleHash(content)` (`markmap: packages/markmap-view/src/view.ts:195-200`).
- **MAP-011** [adapted: 0014] [verify: script] Fenced front matter under `markmap:` honours five safe layout options: `initialExpandLevel`, `maxWidth`, `colorFreezeLevel`, `spacingHorizontal` and `spacingVertical` (clamped to sane numeric ranges; `maxWidth: 0` disables text wrapping up to a 1200 px safety cap). `extraJs`, `extraCss`, `htmlParser` and external script hooks are ignored. markmap: reads all `IMarkmapJSONOptions` and injects `extraJs`/`extraCss` into HTML (`https://markmap.js.org/docs/json-options`, `markmap: packages/markmap-view/src/util.ts:175-230`).
- **MAP-012** [adapted: 0014] [verify: script] Round-trip invariant: every Map mode edit computes the minimal line splice on the note's raw UTF-8 text (which Quire normalises to LF on load in `quire: desktop/src/vault.rs` and `watch.rs`). All lines outside the touched range(s), including front matter, comments, thematic breaks, link definitions, trailing spaces and the note's final newline, remain byte-for-byte identical (`quire: desktop/src/sheet.rs`, `sheet::splice`).

## 2. Editing gestures and Markdown rewrites

- **MAP-013** [adapted: 0014] [verify: script, state] Every committed Map gesture (inline edit, add child, add sibling, delete, drag-and-drop move, keyboard structure move, heading level change, task toggle, image insert, paste) calls `App::ensure_edit`, applies its splice to the active note's `TextEdit` (`App.edits`) inside one `undo_group` (so `e.text` matches the new text before `App::set_text` runs and `App::set_text` never calls `TextEdit::replace_text`, which would discard undo history), then calls `App::set_text` to update the vault (sealing locked notes) and mark the note dirty for Quire's 0.5 s autosave via the background `Writer` thread (`quire: desktop/src/app.rs`, `sheet.rs`). `Ctrl+S` flushes immediately and toasts `"Saved"` (`WR-64`). Saves through the Edit Sheet flush immediately as `SHEET-045` specifies. markmap: read-only, never writes to files.
- **MAP-014** [adapted: 0014] [verify: script] Undo (`Ctrl+Z`) and redo (`Ctrl+Shift+Z` or `Ctrl+Y`) in Map mode operate on the note's shared `TextEdit` history, reversing or reapplying one map gesture per step. Switching between Map, Source and Preview preserves the full undo stack. After undo or redo, the map rebuilds and keeps selection on the affected node, else the nearest node by source line, else the root.
- **MAP-015** [adapted: 0014] [verify: script, state] A locked note shows Quire's lock panel in Map mode and exposes no tree or plain text. Once unlocked, Map edits the plain text in `App.unlocked`, and `App::set_text` seals it via `store_unlocked` before writing to `vault.files` or disk (`quire: desktop/src/lock_app.rs`). Relocking clears the map tree immediately.
- **MAP-016** [adapted: 0014] [verify: script] Double-clicking a text node's label (single-line heading, list item or paragraph), or pressing `F2` or `e` while it is selected, opens an inline text input overlaid at the node's exact position and width. Entering inline edit while zoomed below `0.85` glides to `1.0` centred on the node (restoring the prior camera on `Enter` commit or `Esc` cancel unless manually moved, while staying at `1.0` on `Tab` chaining), and the canvas pans as needed while typing to keep the full field inside the free viewport. A multi-line setext heading opens in the Edit Sheet (`MAP-020`) instead. The input holds the node's raw inline Markdown without its structural prefix (`#` run + space on ATX headings; leading indent, bullet/number marker and task box `[ ] `/`[x] ` on list items) or trailing optional ATX closing `#` sequence or `<!-- markmap: ... -->` directive, and reattaches those verbatim on commit (keeping a single-line setext heading's underline unchanged). Continuation lines in multi-line paragraphs and list-item labels lose their leading indent (up to the item's `content_column`) in the input and get the `content_column` indent back on commit (tabs count to the next multiple of 4 and are written back as spaces). Inline formatting chords (`KEY-50` to `KEY-54`: `Ctrl+B`, `Ctrl+I`, `Ctrl+E` in `omarky` or `Ctrl+Shift+E` in `quire`, `Ctrl+Shift+X`, `Ctrl+K`) act inside the input via `format.rs`.
- **MAP-017** [adapted: 0014] [verify: script] Keys and pointer gestures while inline-editing (`Ctx::MapEdit`, `KEY-145` to `KEY-149`): `Enter` commits the text and keeps the node selected (`Shift+Enter` inserts a newline in paragraph and list-item nodes, and commits in headings); `Esc` cancels and restores the original text (or removes a newly created uncommitted placeholder node with no edit to the file); `Tab` commits the current text and immediately adds a new child node in inline edit; `Shift+Tab` commits the current text and promotes/outdents the node (`MAP-031`); clicking outside the input commits (or discards an untouched new placeholder) and then runs the click on the target. Committed text is written unescaped; the map rebuilds, remaps surviving `NodeId`s (`MAP-010`) and selects the node at `own_lines.start` (falling back to the nearest node by source line if that line no longer produces a node).
- **MAP-018** [adapted: 0014] [verify: script] Committing empty or whitespace-only text on an existing node cancels the edit and restores the node's previous text, so Map mode never writes a bare `# ` or empty bullet. Committing empty text on a newly created uncommitted node removes the placeholder with no file edit and no undo step.
- **MAP-019** [adapted: 0014] [verify: script] Editing the root node depends on its backing source: a real `H1` root edits its `# ` line (preserving setext underline if single-line setext, or opening the Edit Sheet if multi-line setext per `MAP-016`); a virtual root backed by frontmatter `title` updates the `title:` field in front matter, writing the value double-quoted and YAML-escaped (`\\`, `\"`, single-line); a filename-backed virtual root in a note with no top-level `H1` inserts `# <text>` at the top of the body (after front matter if present, with a blank line before following content), promoting it to a real `H1` root; activating edit on a filename-backed virtual root whenever at least one top-level `H1` already exists (whether preceded by content or multiple `H1`s) starts Quire's title-bar rename (`App::start_rename`) in Folder mode and shows the Note mode refusal notice (`App::refuse_in_note_mode`) in Note mode.
- **MAP-020** [adapted: 0014] [verify: script] Pressing `F2` or `e`, or double-clicking a non-image card node (code, diff, table, quote, alert, raw HTML, footnote, front-matter badge) or a multi-line setext heading opens Quire's Edit Sheet (`edit-sheet.md`) scoped to that block's `own_lines` (`blocks::Footnote.lines` for a footnote). Pressing `E` (`Shift+e`) on any non-virtual structural node opens the Edit Sheet scoped to its entire `subtree_lines` (refused on the synthetic `Footnotes` group, `MAP-008`).
- **MAP-021** [adapted: 0014] [verify: script] Add child (`Tab` on a selected container node, or context menu) unfolds the node if folded, places a new placeholder child at the end of its children and starts inline edit. A list item's `content_column` is the visual column where its content starts after its indent, marker and following spaces (tabs count to the next multiple of 4 and are written back as spaces, matching `WR-47`). On commit with text `<T>`: under any heading, pick the child's kind from the heading's last direct heading or list-item child, ignoring leaf content blocks — if it is a subheading of level `L`, insert a level-`L` heading after the parent's `subtree_lines` with blank-line separation; if it is a list item, insert a list item with the same indent and marker style (next sequential number if ordered, `- [ ] ` if task) at the end of the parent's non-heading children (after that item's `subtree_lines` keeping tight or loose spacing per `BLK-22`, or with blank-line separation after any trailing content block); if the heading has no direct heading or list-item children (even if it holds leaf content blocks), insert `## <T>` after `subtree_lines` under `H1` and `- <T>` at the end of its non-heading children under `H2` to `H6`, with blank-line separation; under a virtual root, match the minimum top-level heading level when top-level headings exist, else match the last top-level list item's marker, else insert `- <T>`; under a list item, insert a nested list item after its `subtree_lines` matching any existing child list's indent and marker, else indented to the parent item's `content_column` using the parent's bullet character or `- `.
- **MAP-022** [adapted: 0014] [verify: script] Pressing `Tab` to add a child on a leaf content node (paragraph, code, diff, image, gallery, table, quote, alert, raw HTML) changes nothing and shows the toast `"Only headings and list items can have children"`. Pressing `Tab` on the `Footnotes` group or a footnote child does nothing (`MAP-008`).
- **MAP-023** [adapted: 0014] [verify: script] Add sibling (`Enter` inserts after, `Shift+Enter` inserts before) creates a placeholder sibling and starts inline edit on every non-root editable node (headings, list items, paragraphs and every card including images). On the root node, `Enter` runs Add child (`MAP-021`) and `Shift+Enter` does nothing; on the `Footnotes` group and its children, both do nothing (`MAP-008`). Every sibling insert after goes after `subtree_lines`, and every sibling insert before goes before `own_lines`. On a heading of level `L`, inserts a level-`L` heading with blank-line separation. On a list item, inserts an item with the same indentation and marker style (incrementing ordered number per `MAP-024`, empty `[ ] ` for task items, keeping tight or loose blank-line spacing per `BLK-22`). On a paragraph or card node, inserts a new plain paragraph with blank-line separation; when that node sits inside a list item, the inserted paragraph is indented to the parent list item's `content_column` (tabs count to the next multiple of 4 and are written back as spaces), which makes a tight list loose (`BLK-22`).
- **MAP-024** [adapted: 0014] [verify: script] When inserting, deleting or reordering items inside an ordered list whose items are numbered sequentially from `list.start`, the rewrite updates the affected list's item numbers sequentially while preserving each item's delimiter (`.` or `)`), so Preview (`BLK-27`) and Map display contiguous numbers. When a marker's width changes (for example `9. ` to `10. ` or `10. ` to `9. `), every continuation and child line in that item's `subtree_lines` shifts by the same width delta (clamped at 0; tabs count to the next multiple of 4 and are written back as spaces) so nested blocks stay inside the item.
- **MAP-025** [adapted: 0014] [verify: script] Delete (`Delete` or `Backspace` on a selected node, or context menu) removes the node's entire `subtree_lines`, plus one adjacent blank line only when blank lines (or the file's start or end) bound the removed range on both sides, as one undo step, preserving the note's final newline. Selection moves to the next sibling, else the previous sibling, else the parent. Deleting a subtree with more than one node or a card shows the toast `"Deleted N nodes · <Undo key> to undo"` (using the platform undo label). Deleting the root node, the `Footnotes` group or a footnote child (`MAP-008`) is refused.
- **MAP-026** [adapted: 0014] [verify: script, geometry] Dragging any non-root structural node (excluding the `Footnotes` group and its children, `MAP-008`) past `6 px` begins a drag-and-drop move: a translucent ghost of the node (with a `+N` badge when carrying descendants) follows the pointer, and the source subtree dims to opacity `0.35`. Holding the pointer within `36 px` of a viewport edge auto-pans at up to `480 px/s`. Hovering a valid container target splits its hit box into Before (top 25%, accent bar above), Child (middle 50%, accent box + branch stub on right) and After (bottom 25%, accent bar below); leaf targets split 50%/50% into Before and After only. Before and After drop bands are at least `8 screen px` tall and extend into half the vertical sibling gap. Drop zones that `MAP-027` to `MAP-030` disallow do not show. Dropping on the dragged node, its own descendant or empty canvas, or pressing `Esc`, cancels with no change.
- **MAP-027** [adapted: 0014] [verify: script] Drop-zone placement and heading move rule (heading moved under a heading or virtual root): a heading takes Before/After zones only on heading siblings; a non-heading node takes Before/After zones only on non-heading siblings, plus Before the first subheading; a Child drop on a heading or virtual root puts a non-heading at the end of its non-heading children (before its first subheading, if any) and a heading at the end of its subtree. Other zones do not show, and keyboard moves (`MAP-031`) stop there. When moving a heading, `target_level` is the target heading sibling's level (for Before/After), or `parent.level + 1` (for Child of a heading), or the minimum top-level heading level under the virtual root (else `source.level`, for Child of a virtual root), and every heading in the moved subtree shifts by `delta = target_level - source.level`. Setext headings keep setext syntax when `delta == 0` and become ATX when `delta != 0`. Non-heading lines inside the moved subtree stay byte-for-byte identical. If any heading in the moved subtree would exceed `H6`, the zone does not show and the move is refused (`MAP-029`).
- **MAP-028** [adapted: 0014] [verify: script] List-item move rule (list item moved under a list item, heading or virtual root): follows the `MAP-027` non-heading zone rule (Before/After only on non-heading siblings plus Before the first subheading; Child on list items, headings or the virtual root) and never converts a list item into a heading. The marker line gets the target's indent and marker style (preserving any `[ ] `/`[x] ` task box; matching an existing target list's indent and marker, or an existing child list when dropped as Child of a list item else the parent's `content_column` and bullet or `- `, or indent 0 keeping its own marker style when dropped as Child of a heading or virtual root with no trailing list). Every other non-blank line in the moved subtree shifts by `new_content_column - old_content_column`, clamped at 0. Tabs count to the next multiple of 4 and are written back as spaces. Dropping a list item as a Child of a heading or virtual root places it at indent 0 at the end of that parent's non-heading children (before its first subheading, if any).
- **MAP-029** [adapted: 0014] [verify: script] Cross-kind and `H6` boundary refusal: in v1, a drag or keyboard move never converts a heading into a list item or a list item into a heading, and never shifts any heading past `H6`. A heading shows no Child drop zone on a list item and no Before/After zones on non-heading siblings; a non-heading node shows no Before/After zones on headings except Before the first subheading; any heading target where `max_heading_level + delta > 6` shows no drop zone. Cross-kind conversions and `H7+` fallback to bullets are deferred (`MAP-083`).
- **MAP-030** [adapted: 0014] [verify: script] Non-list content block move rule (paragraph, code, diff, image, gallery, table, quote, alert, raw HTML): follows the `MAP-027` non-heading zone rule (Before/After only on non-heading siblings plus Before the first subheading; Child on headings, the virtual root or list items). Moving between headings or the virtual root splices raw lines verbatim with blank-line separation at the end of the target's non-heading children (before its first subheading, if any). Moving under or between list items shifts every non-blank line by `new_content_column - old_content_column`, clamped at 0 (where `old_content_column` is 0 at top level or the source parent item's `content_column`; tabs count to the next multiple of 4 and are written back as spaces), with blank-line separation (making a tight list loose per `BLK-22`). Moving out of a list item to a heading or virtual root shifts every non-blank line by `0 - old_content_column`, clamped at 0.
- **MAP-031** [adapted: 0014] [verify: script] Keyboard structure moves run the exact same placement, rewrite and refusal rules as `MAP-027` to `MAP-030`: `Alt+Up` moves Before the previous sibling; `Alt+Down` moves After the next sibling; `Shift+Tab` or `Alt+Left` promotes/outdents to After the parent; `Alt+Right` demotes/indents to Child of the preceding sibling. Whenever the target zone is disallowed by `MAP-027` to `MAP-030` (such as crossing a heading/non-heading sibling boundary, moving a heading into a list item, promoting a non-heading out of a heading, or shifting any heading past `H6`), the move stops in place and shows a short toast. `Ctrl+Alt+1` to `Ctrl+Alt+6` (`KEY-128`) act on headings only in v1, setting the selected heading to level `1` to `6` and shifting its descendant headings by `delta = new_level - old_level` (preserving setext when `delta == 0`, switching to ATX when `delta != 0`, and refusing with a short toast if any descendant heading would exceed `H6`); on non-heading nodes they do nothing and show a short toast (converting non-headings and the Convert menu are deferred in `MAP-083`).

## 3. Canvas, layout and visuals

- **MAP-032** [adapted: 0014] [verify: geometry] The map canvas fills the full note area (`doc-area`) on `Roles::bg`, with no scrollbars, no reading column cap and no linear progress bar (`RD-37`).
- **MAP-033** [adapted: 0014] [verify: script] Infinite pan works with no coordinate bounds via left-dragging empty canvas space, middle-dragging anywhere, touchpad two-finger swipe (scaled at 12 points per compositor unit per `RD-26`), and mouse wheel (vertical pan, `Shift+wheel` horizontal pan, 60 px per notch), everywhere on the canvas including over cards. A touchpad swipe throws the camera on when the fingers lift, with `RD-27`'s release velocity and Chrome's fling curve, along the swipe's direction and at most three canvas extents; a new swipe, a wheel step, a drag, a pinch or a camera glide stops it. Fingers resting on the touchpad do not stop it, since Rune keeps the hold gesture to its own scroll views, and two quick swipes do not add up (`RD-27`'s boost) (`Space`+drag pan is deferred in `MAP-086` and internal card scrolling is deferred in `MAP-085`). markmap: wheel zooms on Linux/Windows and pans only on macOS (`scrollForPan: isMacintosh`, `markmap: packages/markmap-view/src/constants.ts:152`).
- **MAP-034** [adapted: 0014] [verify: script, state] Zoom scales the canvas between `0.1` (10%) and `4.0` (400%): `Ctrl+wheel` and trackpad pinch zoom smoothly anchored at the pointer position (on Wayland the pinch comes from `zwp_pointer_gesture_pinch_v1`, which `desktop/vendor/winit` binds); `+` and `=` zoom in by `× 1.25` and `-` zooms out by `× 0.8` anchored at the viewport centre (`markmap: packages/markmap-toolbar/src/toolbar.tsx:90-95`). `Ctrl+=`/`Ctrl++` and `Ctrl+-` stay Quire's global text-size keys (`KEY-21`, `KEY-22`), and zooming the canvas never changes `Settings.size`. `Ctrl+0` resets canvas zoom to `1.0` centred on the selected node (or root).
- **MAP-035** [adapted: 0014] [verify: geometry, script] Fit to view (`0` or the title bar Fit button) computes the bounding box of all currently unfolded nodes and sets scale to `min((free_w / bounds_w) × 0.95, (free_h / bounds_h) × 0.95, 2.0)` clamped to `[0.1, 4.0]`, centred inside the viewport area clear of an open Find bar or toast band (`markmap: packages/markmap-view/src/view.ts:623-646`).
- **MAP-036** [adapted: 0014] [verify: script, geometry] Centre on node (`c`) pans at the current zoom to place the selected node's centre at the centre of the free viewport (`markmap: packages/markmap-view/src/view.ts:709-739`).
