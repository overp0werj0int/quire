# Board mode

Board mode shows a `kanban-plugin` note as a kanban board: its root headings as columns and task
items under each as cards (decision 0015). It is the fourth mode, beside Source, Preview and Map.
It reads the tree Map mode reads (`map.md`, section 1) and moves a card with Map mode's own move,
so the note's Markdown stays the one source of truth.

Notes on reading this file:

- The format and status tags follow `README.md`. Every in-scope item uses `[adapted: 0015]`.
  Items are checked by behaviour: a `script` item is a case in `desktop/tests/cases/board/` that
  replays input on a note and checks the note on disk or a probe reading.
- `B` is the body size setting (`PAGE-10`), 14 px by default. Values in brackets are for
  `B` = 14 and scale with `B / 14` unless marked fixed.
- Colour names are the page roles of `map.md`. "The tree", "the root", "a node" and
  `subtree_lines` are Map mode's (`MAP-001` to `MAP-010`).

## 1. The note as a board

- **BRD-001** [adapted: 0015] [verify: script, state] Board mode is gated to unlocked notes whose front matter declares `kanban-plugin` (not `false`, `no`, or `off`), read from `blocks::Kind::FrontMatter` (`board::is_kanban`). Other notes hide the Board mode button and command, refuse `Ctrl+Shift+K` with a toast, and leave Board mode if switched to or edited to remove `kanban-plugin`. Opening a kanban note with no saved mode state enters Board mode automatically.
- **BRD-002** [adapted: 0015] [verify: script, state] A column is a heading that is a child of the root (`MAP-002`), in note order. With a lone `H1` as the root these are its `H2`s, or whatever headings sit directly under it (`MAP-003`). With a virtual root they are the note's top-level headings. Empty heading columns remain visible with count `0` so cards can be dropped into them.
- **BRD-003** [adapted: 0015] [verify: script, state] A card is a task list item (`- [ ]` or `- [x]`) directly under a column heading, in note order. Non-task bullets, paragraphs, subheadings, code/table/image/quote blocks, loose root content and `Footnotes` are not shown as cards.
- **BRD-004** [adapted: 0015] [verify: script, state] A task card with direct child task items carries a folding handle (`board-fold:{id}`) and colored subtask dots (`board-dots:{id}`): one dot per direct subtask in the column's branch colour, solid for done (`- [x]`) and outlined for incomplete (`- [ ]`). Subtasks start folded; toggling the folding handle (or `Space`) unfolds direct subtasks as nested sub-cards obeying the exact same rules recursively (click-to-preview mini window, own folding handle and dots, drag-and-drop).
- **BRD-005** [adapted: 0015] [verify: script, state] Non-task child blocks indented under a task item (paragraphs, code, images, tables, quotes, plain lists) stay inside the task's content rather than becoming cards, and show a quiet details mark (`board-body-mark:{id}`) on the card.
- **BRD-006** [adapted: 0015] [verify: script, geometry] A kanban note with no column headings shows a quiet line in `styles::desc()` (`caption_ink`): `Headings become columns and tasks become cards. Add one in Source to start a board.`

## 2. Layout and look

- **BRD-007** [adapted: 0015] [verify: geometry] The board fills the note area on `bg`. Columns sit in a row from the left with `round(B × 12 / 14)` [12 px] between them and `round(B × 16 / 14)` [16 px] round the row. When the row is wider than the area it scrolls sideways through Rune's native scroll and throw engine (`El::scroll_x`, decision 0012 — inertial coast, fling boost, `touchpad_hold` stop, and eased `Shift+wheel` with no custom `on_wheel`), or by a drag on empty board. There is no reading column and no progress line.
- **BRD-008** [adapted: 0015] [verify: geometry] A column is `round(B × 20)` [280 px] wide. It is a `panel` surface with a `1 px` `hairline` border, `10 px` radius (`radius::COLUMN`) and `8 px` padding, as tall as its cards and never taller than the area: past that its cards scroll inside it, under its header, with the scroll-edge fades the Edit Sheet uses (`ui::components::faded_h`).
- **BRD-009** [adapted: 0015] [verify: geometry] A column's header is one row: a `3 × 14 px` bar in the column's branch colour (`MAP-040`), the heading's inline runs in bold `B` in `strong`, cut to one line with an ellipsis, and at the right end the number of its top-level task cards in `ui::components::count_pill`.
- **BRD-010** [adapted: 0015] [verify: geometry, golden] A card is a `card` surface with a `1 px` `hairline` border, an `8 px` radius (`radius::FIELD`), `8 px` top and bottom and `10 px` side padding, and `6 px` between cards. Its label uses the reader's inline runs (`ui::map::label`), wrapping at the card's inner width. Unfolded sub-cards sit indented `12 px` (`space::PX_12`) beside a `2 px` branch-coloured rail and animate open and closed on `motion::layout_glide_spring()`.
- **BRD-011** [adapted: 0015] [verify: geometry, script] Because every board card is already a task, cards omit checkboxes on the board surface and distinguish done tasks with `dim` label text (`BLK-31`); users toggle completion via `x` or the interactive checkbox in the Card Mini Window header. When a card has subtasks, its metadata row holds the `24 × 24` folding handle (`CHEVRON_RIGHT` / `CHEVRON_DOWN`, 10 pt) and `ui::components::progress_dot` dots contrast-lifted to `>= 3.1:1` on the card surface.
- **BRD-012** [adapted: 0015] [verify: geometry] Hovering an unselected card or column header fades `hover` over it in `100 ms` (`motion::hover_fade()`). The selected card, sub-card, or column header uses the shared sliding selection glass (`ui::components::SelectionGlass`, keys `board-selection` / `board-glass`) gliding smoothly between items on Rune's spring while gently zooming the selected item (`SelectionGlass::scale_for`), and keyboard/find/outline selection glides the board canvas and column scroll smoothly (`tx.scroll_to`). Exactly one visible card or column header is selected, or none on a board with neither.
- **BRD-013** [adapted: 0015] [verify: script] Theme, accent and text size changes restyle the board live. Switching to Board plays the mode fade (`WR-109`), and a tab switch slides as in the other modes.

## 3. Holding and dropping a card

- **BRD-014** [adapted: 0015] [verify: script, geometry] A press on a card or sub-card that travels past `6 px` lifts it. The held card is the card itself, scaled gently (`1.02×` outside reduced motion), drawn over everything on the board with `Elevation::Dialog` and an `accent`-tinted border. It follows the pointer, holding the point it was pressed at. A press on a link or a folding handle acts as that control and lifts nothing.
- **BRD-015** [adapted: 0015] [verify: script, geometry] The held card is tilted. On the lift it turns `3°` clockwise about the point it is held at. While it travels sideways it leans the way it goes: the tilt's sign is the sign of its horizontal travel (clockwise to the right, counter-clockwise to the left) and its size goes from `3°` at rest to `6°` at `1200 px/s` or more. Travel under `4 px` between frames keeps the last sign, so a still hand holds a still card. The tilt changes on a `120 ms` spring (`El::rotate`, `El::rotate_motion`). On release the card turns upright as it settles (`BRD-019`).
- **BRD-016** [adapted: 0015] [verify: script, geometry] The held card's old place closes: the cards under it move up. A slot opens where a drop would put it: a gap as tall as the held card, with a `1.5 px` dashed `accent` outline at 55% and an `accent` wash at 10%, `8 px` radius, fading in on `motion::modal_spring()`. The cards at and after the slot move down to make it on the `180 ms` layout glide (`motion::layout_glide_spring()`).
- **BRD-017** [adapted: 0015] [verify: script] The slot follows the pointer across columns and unfolded subtask lists (`SlotParent::Column` or `SlotParent::Card`). In the target list the slot goes before the first remaining card whose middle is below the held card's middle, else at the end. A slot that `map::zone` refuses moves to the nearest slot in that parent it allows. When no slot is allowed there is none, the held card shows the refusal cue (a `dim` wash and the reason under it), and a release shows the reason as a toast and changes nothing.
- **BRD-018** [adapted: 0015] [verify: script] Holding the pointer within `36 px` of the board's left or right edge scrolls the row at up to `480 px/s`, and within `36 px` of a column's top or bottom scrolls that column's cards.
- **BRD-019** [adapted: 0015] [verify: script] A release over a slot moves the card: `map::move_to` to the slot's place (before the card after it, else after the card before it, else as the parent's child), applied by `App::map_apply` as one undo step (`MAP-013`). The card glides from the pointer into the slot, scales back to `1.0×`, and turns upright over `180 ms`, stays selected, and its column scrolls by the least that shows it whole. A release in the slot the card came from writes nothing. `Esc`, or a release with no slot, puts the card back with the same glide and writes nothing.
- **BRD-020** [adapted: 0015] [verify: script] A moved task takes the target list's marker and indent and both lists renumber, moving its entire subtree (`span`) atomically. A drop into an empty column makes the task that column's first child (or before any subheading). Lines outside the two places stay byte for byte (`MAP-012`).
- **BRD-021** [adapted: 0015] [verify: script, geometry] A press on a column's header that travels past `6 px` lifts the whole column, tilted by the rule of `BRD-015` at half the angles. A slot as wide as a column opens between columns where a drop would put it, and a release moves the heading with everything under it before or after the other heading (`MAP-027`).
- **BRD-022** [adapted: 0015] [verify: script] Under reduced motion (`PAGE-84`) the held card has a fixed `3°` tilt with no lean or lift scale, and nothing glides: cards, folds, the slot and the settle land at once.
- **BRD-023** [adapted: 0015] [verify: script] While a card or column is held, no hover shows, wheel and swipe still scroll, and a change to the note from outside (`RD-01`) ends the hold with nothing written.

## 4. Card mini window, selection, keys and the rest of the window

- **BRD-024** [adapted: 0015] [verify: script, state] The board's selection is the tab's map selection (`MAP-044`): clicking a column header selects it, clicking a card selects it and opens its mini window, and switching between Map and Board keeps the node (projecting nested or folded nodes to the deepest visible card or column header). Switching to Source or Preview goes to the selected node's line, as from the map.
- **BRD-025** [adapted: 0015] [verify: script] `Up`/`k` and `Down`/`j` select the previous and next visible card (walking into unfolded sub-cards) in the column, and from the first card the column's header. `Left`/`h` and `Right`/`l` select the visible card at the same height in the next column that way, else its last visible card, else its header. From a column's header they select the next column's header that way, so `Home`, `Right` and `Alt+Right` walk and move columns. `Home` selects the first column's header. The board scrolls by the least that shows the selection.
- **BRD-026** [adapted: 0015] [verify: script] `Alt+Up` and `Alt+Down` move the selected card (or sub-card) one place within its parent list. `Alt+Left` and `Alt+Right` move it to the end of the next column that way, and on a column header move the column. Each is the move a drop there would be (`BRD-019`), and a move the rules refuse shows its toast and changes nothing.
- **BRD-027** [adapted: 0015] [verify: script] Clicking a card body or pressing `Enter` (`board.open`) opens the **Card Mini Window** (`Layer::Sheet` with `CardView`, built on `components::MiniCard`) in Preview mode displaying all content under the node via `ui::preview::render_blocks`, with a left-side interactive task status pill (`Open`/`Done`) and a header/footer hover-revealed top-right icon mini-bar (`[✎ Edit] [× Close]`, `×` rightmost). Clicking the Edit icon (or pressing `e` / `F2` from Preview) switches in-place with `ui::swap()` into Edit mode (`[✓ Save] [× Cancel/Discard]`) where `Esc` and saving return to Preview; opening Edit directly from the board (`e` / `F2` / menu) returns straight back to the board on `Esc` or save. Saving (`Ctrl+Enter`, `Ctrl+S`, or `✓`) writes through `App::map_replace` + `flush_notes` as one undo step. `PageUp`/`PageDown`/`Home`/`End` work inside the mini-card's preview and editor. `x` (or clicking the status pill in the mini window header) toggles the task (`MAP-053`). `Space` toggles subtask folding (`board.toggle-fold`). `Delete` or `Backspace` deletes the selected card with Map's toast (`MAP-025`), and is refused on a column header with `Delete a column in Source or on the map`. `Ctrl+C` copies Markdown. `Ctrl+Z` / `Ctrl+Shift+Z` / `Ctrl+Y` undo and redo. `Ctrl+Enter` follows the card's first link.
- **BRD-028** [adapted: 0015] [verify: script] A right-click on a card opens a menu layer with Open, Edit, Fold/Unfold subtasks (when it has subtasks), Copy, Move to (one item per other column) and Delete.
- **BRD-029** [adapted: 0015] [verify: script, state] `Ctrl+Shift+K` (`app.mode-board`) switches to Board on a kanban note and back to the last linear mode (`Source` or `Preview`). The title bar's mode control shows the Board segment after Map on kanban notes, and the command palette lists `Switch to Board` there. `state.json` names the mode `board` and keeps explicit per-note mode overrides in `Session::note_modes`. The board's keys live in `Ctx::Board` (falling through to `Ctx::Global`), listed in `keymap.md` and on the help sheet.
- **BRD-030** [adapted: 0015] [verify: script] Find (`Ctrl+F`, `/`) matches column titles and task card labels (including folded subtasks, unfolding ancestors on jump) in note order and selects and shows the match. The outline's current entry is the heading the selection is under, and a click on an entry selects that heading's column.
- **BRD-031** [adapted: 0015] [verify: bench] A drag frame runs no parse of the note and builds again only the held card, the slot and the columns whose cards moved. A board of 20 columns and 2,000 cards keeps drag frames under `16 ms`.
